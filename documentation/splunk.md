# Splunk SIEM Monitoring

## Overview

Splunk was used as the SIEM platform for collecting, searching, and analyzing security telemetry generated by the Windows environment.

## Log Sources

The lab generated security telemetry from Windows systems, including:

- Windows Security Events
- Sysmon telemetry
- Authentication activity
- Account creation events

## Windows Events in Splunk

Windows security events were searched and analysed through Splunk to identify authentication and endpoint activity.

![Windows Events in Splunk](../screenshots/splunk/windows-events-in-splunk.png)

## Successful Authentication

Windows Event ID 4624 was used to investigate successful authentication activity.

![Successful Logon](../screenshots/splunk/successful-logon-event.png)

## Failed Authentication

Windows Event ID 4625 was analysed to identify failed authentication attempts.

![Failed Logon](../screenshots/splunk/failed-logon-event.png)

Repeated failed authentication attempts can be useful indicators when investigating potential password guessing or account abuse.

## Multiple Failed Logins

Multiple authentication failures were analysed to identify patterns of repeated failed logon attempts.

![Multiple Failed Logins](../screenshots/splunk/failed-logon-event.png)

## Investigation Workflow

The investigation process involved:

1. Searching for relevant Windows events
2. Filtering events by Event ID
3. Reviewing timestamps and affected accounts
4. Investigating source information
5. Correlating related events
6. Determining whether activity was expected or suspicious

## Key Findings

The lab demonstrated how Windows authentication telemetry can be searched and investigated using Splunk.

The generated events provided realistic data for practicing SOC-style authentication monitoring and investigation.
